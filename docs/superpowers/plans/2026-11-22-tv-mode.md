# TV Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Mac on HDMI, Chrome full-screen, a DualSense over Bluetooth: the whole game, start to finish, from the sofa, with couch-sized text and button pictures.

**Spec:** `docs/superpowers/specs/2026-11-22-tv-mode-design.md`

**Architecture:** A tiny seam in start-up (`src/tvseam.js`) plus ONE lazy chunk (`src/tv/*`, with `tv.css`) loaded only when `settings.tvMode` is on. The chunk sets `html.tv` (scale and safe margins), tracks the last-used input for glyphs, owns the letter-picker card, the auto-offer, the disconnect pause and the pixel budget. Existing pad code (`gamepad.js`, `gamepadnav.js`) gains a few small hooks and the audit fixes.

**Tech stack:** vanilla JS, vite (dynamic import = own chunk), vitest, plain CSS.

## Global constraints (every task)

- Work only in `.worktrees/tv-mode` (branch `tv-mode`). Never touch the main checkout, never push, never merge without the owner's yes. The live database is off limits.
- **Start-up ceiling 720 kB gzipped, never raised.** Baseline 703.5 kB (headroom 16.5). The start-up seam may add at most ~1.5 kB; stop and re-plan if start-up passes 706.0 kB. TV code lives in `src/tv/` and is reached only through `import('./tv/index.js')`.
- Fair chunk stays 96.1 / 100 kB: this plan does not touch it.
- **No save change.** `tvMode` and `tvOfferDeclined` are device settings (`whisker-walk-settings`), which `settings.js` sanitises and the save and cloud save never see. If a task ever wants a save field, stop: it needs a migration plan and a cloud-sanitiser note first.
- Offline-first: the chunk is listed in `precache.json` automatically (every file under `assets/`); no network at play time.
- **Test running:** run only the named test files while building (`npx vitest run test/<file>`). The full suite (`npm test`) runs once per milestone, never between 18:30 and 19:30 local. Check `date` first.
- Touch, mouse and keyboard with TV mode off must not change at all: the seam functions are identity or no-ops.
- Text goes through word tables, for BOTH word sets ('on' and the everyday 'off' set). No new English strings in a `.js` UI file.
- Real-pad checks are the owner's, on his DualSense on the Mac. Agents test with a fake `navigator.getGamepads` and the browser pane, and say so.
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review focus (for the final review of each milestone)

## What the code does today (read 2026-11-22, main 34112f3e)

- `src/gamepad.js` polls once a frame from `walkFrame()` (`main.js:1194`). Mode `walk` (engaged or a clan fight), `menu` (navigator), `none` (the "Off to ..." crossing). Disconnect only releases the stick (`gamepaddisconnected`). `setRing()` adds `body.pad-focus` on the first pad use; `pointerdown`/`keydown`/`touchstart` remove it. Only `mapping === 'standard'` pads count.
- `src/gamepadnav.js` + `gamepadnavcore.js`: layers (`[data-pad-layer]`, then `#overlay`, then `#homebase`), directional pick, press (click / Enter on SVG), range nudge, select cycle, scroll, map pan/zoom, `settle()` focuses a new screen's entry control (`data-pad-default`, then `.primary`, then the first). Text-like inputs are skipped on purpose.
- Key hints are hard-coded in several places: `KEY_STRIP` (`ui/hud.js:70`), `KEYS_HINT` and `chatHintLine` (`game/walk.js:326-331`), the den shop hint (`ui/denshopview.js:61`), the viewfinder hint spans (`hud.js`), fight keys `E`/`Q`/`1-3` (`ui/fightui.js:37-102`), and the 29 `two(touch, keys)` lines in `tutorialwords.js` (`hint.*`, `how.*`, `guide.*`). `line(id, {touch})` returns plain text; `WORDS` entries must be exactly `{touch, keys}` (`test/tutorialwords.test.js`), so the pad form cannot be added to that table.
- Settings: `settings.js` `DEFAULTS` + `sanitize` + `set` (a boolean falls into the generic branch). Switches are drawn by `settingsSwitchHtml` in `homebase.js renderControls()` and wired by id in `homebase.js` (~2457-2482). Settings are device-only.
- Render size: `renderer.setPixelRatio(min(dpr, 1.5|2))` at boot (`main.js:151`); each walk sets it again in `game/adaptquality.js:126` (`min(devicePixelRatio, tier.pixelRatioCap)`, rung caps 2 / 1.5 / 1); `window.resize` resizes the size only (`main.js:716`), never the ratio, so plugging in a TV mid-session keeps the old ratio until the next walk. Composer target sized from `window.innerWidth/Height` (`game/composer.js:80-105`).
- Build checks: `scripts/buildjson.mjs` (`MAIN_GZIP_CEILING_KB = 720`, `lazyProblems`, `areaSizeProblems`, `AREA_GZIP_CEILING_KB = 100`), `test/buildsize.test.js`, `test/iosbundle.test.js` (iOS bundle ships dynamic chunks).
- HUD sizes today (px at 16 px root): points 19, rank 16, area 13, roster chip 13, objective 15, goals 14, goal "how" 13, hint 18, toast 17, controls strip 14, viewfinder hint 14. Safe areas use `max(16px, env(safe-area-inset-*))`. Corner map is `--map-size: 150px` (110 on touch).
