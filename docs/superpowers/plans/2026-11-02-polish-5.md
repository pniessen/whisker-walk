### Task 4: The walk camera handles trees (fade what is between it and the cat)

**Files:**
- Create: `src/treefade.js`
- Modify: `src/game/walk.js:1426` (compute `findOccluders(scene)` once and share it between the fight camera and the tree fade), the session setup (add `session.treeFade`), endWalk (`session.treeFade?.dispose()` next to `session.fightCam?.dispose()` ~1922)
- Modify: the render loop (in `src/main.js`, where `session.fightCam.update` runs) — call `session.treeFade.update(dt, camera, catLook)` AFTER `player.update` and AFTER the fight camera has placed the camera, every walk frame (the den gets no fade: pass an empty occluder list or a no-op stub as the render loop does for skyLife)
- Test: `test/treefade.test.js`

**Interfaces:**
- Consumes: `findOccluders(scene)` and `segmentBlocked(a, b, occ, pad)` from `src/fightcam.js` (both exported today).
- Produces: `createTreeFade(occluders, { reducedMotion = false } = {}) → { update(dt, camera, look), faded(): Set<object>, dispose() }` where `look` is `{ x, y, z }` (the cat at `CAT_LOOK_Y`), and `faded()` returns the Groups currently below full opacity (for tests).

**Rulings:**
- Which trees: an occluder with an `obj` (a single tree Group: oak, willow, pine) is "in the way" when the segment from the camera position to `look` passes through it with `segmentBlocked(cam, look, occ, 0.15)`, OR the camera is inside its padded bounding cylinder (`hypot(cam - occ) < occ.R` and `cam.y < occ.top`). Quick reject first: skip any occluder whose `hypot(occ.x - look.x, occ.z - look.z) > camDist + occ.R` (camDist = distance camera↔look), so a frame costs one subtraction pair per tree for the far ones.
- Fade: an in-the-way tree eases to opacity `0.28` over ~0.2 s, and back to 1 over ~0.4 s once clear; reducedMotion snaps. Fading swaps each mesh's material for a per-tree clone made on first fade (`transparent: true`, `depthWrite: false` while below 1, same `onBeforeCompile` and `customProgramCacheKey` as the original, because `Material.clone()` does not copy them), and swaps the original back when the tree reaches 1 again (keep the clone cached for reuse; dispose all clones in `dispose()`). Never touch `obj.visible` (fightcam owns that). The shared original material object is never mutated.
- Stand trees (`obj === null`, merged pine stands): left alone in this pass (they cannot be faded one by one without per-instance work). Record this as a parked item in the report; no camera pull-in, since anything inside player.update would change the flat trace.
- Cost: no allocation per frame after warm-up (reuse vectors/objects); the occluder list is built once per walk.
