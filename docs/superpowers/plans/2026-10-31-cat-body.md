# Cat Body Reshape Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the "baguette with legs" cat body with the approved Version 2 shape (shorter body on longer legs, a shaped torso with painted coats, strong hind legs, a chest under the chin and a rooted curling tail), keeping the cute head, every coat, every pose and every accessory working at no extra draw calls.

**Architecture:** The torso becomes ONE vertex-coloured mesh built by `torsoGeometry()` (the sketch's `catTorso()` deformation) in a new `src/cat/torso.js`, painted by `paintCoat()` in a new `src/cat/coat.js`. Extra shapes (chest, thighs, tail joints) are merged into meshes that already exist. The animator treats every cat as a long-legged cat measured against the old "reference rig", so existing pose numbers keep working, and it takes ownership of the tail's curl.

**Tech Stack:** Three.js 0.185 (`three`, `three/examples/jsm/utils/BufferGeometryUtils.js`), Vitest 4, Vite 8. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-31-cat-body-design.md`. The visual target is the "Version 2" code in `cat-shapes.html` (session scratchpad, r128). Every number below marked *(sketch)* is copied from it.

## Global Constraints

- Three.js stays at 0.185; no new npm dependencies.
- **Mesh count per cat never goes up.** Final ceilings (full / simple): tabby 30/24, siamese 30/24, persian 30/24, black 30/24, calico 31/25, mainecoon 30/24, zeetoo 30/24, robbie 31/25, d2 31/25, digit 34/28, hagrid 19/19.
- **Triangle caps:** a bare full cat ≤ 8,000 triangles; a bare simple cat ≤ 5,500.
- **Hagrid is byte-identical** through every task (`buildChicken` is not touched; the animator's changes are no-ops for a rig without `tailCurl` / `legLift`).
- **Determinism:** nothing in the model reads `Math.random`, `walkRng` or time. The same breed and accessories build the same geometry and colours.
- **The head is unchanged** except `head.position = (0, 0.70, −0.40)` and `head.scale = 1.06` *(sketch)*. Whiskers are drawn exactly as today.
- **Nothing on the wire changes:** profiles still carry `{ breed, accessories }`; `SAVE_VERSION` is untouched.
- Painted colours are built with `new THREE.Color(hex)` (linear working space), so a painted base matches today's `material.color` exactly.
- Torso material: `litMaterial(0xffffff, { vertexColors: true })`.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Each task regenerates the golden fingerprints deliberately (`UPDATE_GOLDEN=1`). The commit message lists which presets' goldens changed, and the diff must match the task's "Expected golden changes" line.

- [ ] **Step 3: Implement**

`deformTorso` is the sketch's loop body, verbatim in its maths, with the constants named:

```js
const front = Math.max(0, -z), back = Math.max(0, z);
const waist = Math.exp(-((z - S.waistZ) ** 2) / S.waistW);
let kx = 1 - S.waist * waist + S.hips * back * back;
let ky = 1 + S.chest * front - S.waistDrop * waist;
if (y < 0) ky *= 1 + S.chestLow * front - S.tuck * back * back;
const haunch = Math.exp(-((z - S.haunchZ) ** 2) / S.haunchZW) * Math.exp(-((y - S.haunchY) ** 2) / S.haunchYW);
kx *= 1 + S.haunch * haunch;
x *= kx; y *= ky;
if (y > 0) y += S.backRise * (z + 1) * 0.5 * (1 - x * x);
return [x, y, z];
```

`torsoGeometry`:
1. `new SphereGeometry(r, wSeg, hSeg)`.
2. `.rotateX(π/2).rotateZ(π/2)`. This puts the poles at nose and rump (under the chest and tail root) and the seam along the belly.
3. Delete `uv` and `normal`, then `mergeVertices`.
4. Record unit directions, deform each vertex by `deformTorso(p/r) × r`, then `computeVertexNormals`.

In `model.js`, the body mesh becomes `new THREE.Mesh(torsoGeometry(TORSO.R, ...TORSO.SEG[opts.simple ? 'simple' : 'full']), mat(s.base))` with `scale = BODY_SCALE`. Until Task 4, body patches are lifted onto the deformed surface: `patchGeometry` gains an optional `deform` argument (applied to each unit vertex before `× r × PATCH_LIFT`), and body markings pass `deformTorso`.
