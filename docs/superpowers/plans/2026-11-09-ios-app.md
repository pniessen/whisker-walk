# Whisker Walk 2 iOS App Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A home-screen app, **Whisker Walk 2**, for iPhone and iPad that runs the bundled web game full screen, keeps its save, never behaves like a browser, and is refreshed weekly on every family device by one command.

**Architecture:** A second Vite build of the unchanged game (`--mode ios`, relative base, no service worker) lands in `ios/web/`. A small UIKit app in `ios/` copies that folder into its bundle and serves it to one full-screen `WKWebView` through a custom `whiskerwalk://` scheme, so the game has one stable origin for `localStorage`. A Node script (`ios/refresh.mjs`) builds, signs with the free Personal Team, and installs over the top on every reachable device.

**Tech Stack:** Vite 8 / Vitest 4 (existing), Swift 6.4 + UIKit + WebKit, XCTest, Xcode 27.2 (`xcodebuild`, `xcrun devicectl`), Node 26 (from mise).

**Spec:** `docs/superpowers/specs/2026-11-09-ios-app-design.md`

## Global Constraints

- Work on branch `ios-app` in `.worktrees/ios-app`; merge to `main` with a `Merge ios-app: …` commit like the rest of the history.
- Bundle id `com.pniessen.WhiskerWalk`; display name `Whisker Walk 2`; team `CWCZY9U9A8` (free Personal Team).
- iOS/iPadOS deployment target **17.0**; `TARGETED_DEVICE_FAMILY = 1,2`; iPhone: portrait + landscape left/right; iPad: all four; `UIRequiresFullScreen = YES`.
- No new npm dependencies. No third-party iOS frameworks or packages.
- `npm run build` output must stay byte-for-byte what it is on `main`; `npm run dev`, `npm test`, `.github/workflows/*` and `test/fixtures/flat-trace.json` unchanged.
- Never commit `.env.local`, `ios/web/`, `ios/build/`, `xcuserdata/`.
- The refresh never uninstalls; it always installs over the top.
- Launch/background colour `#1c2431` (the game's splash and `theme-color`).
- Node in non-interactive shells: `zsh -ic '…'`.

## Review Focus

1. **A refresh on day 3 reuses the cached, unexpired free profile**, so the "fresh" install still dies on day 7 of the *old* profile. Expected: every refresh produces a new 7-day profile, and the script prints the real expiry read from the installed app's `embedded.mobileprovision`, warning if it is under 6 days away. → Task 4 tests `profileMatches` and `summarize`'s warning; Task 4 Step 9 checks it on a real build.
2. **iPadOS kills the web content process while the app is in the background** (memory pressure on an older iPad), and the child comes back to a blank dark screen. Expected: the game reloads itself (the save is in `localStorage`, so only the walk is lost, as agreed). → Task 3 handles `webViewWebContentProcessDidTerminate`; Task 3 Step 6 forces it on the simulator.
3. **Odd request URLs reach the scheme handler**: `?perf`, `#fragment`, `%20`-encoded names, `..` segments, a missing file, an unknown extension. Expected: query and fragment ignored, encoded names decoded, nothing outside `web/` ever served, a 404 instead of a crash, `.js` always `text/javascript` (otherwise ES modules fail and the screen stays blank). → Task 2 `WebRootTests`.
4. **Typing with the on-screen keyboard while scrolling is disabled**: the pet name and the Sync ☁️ save-code field. Expected: the field stays visible and typeable on an iPhone in portrait, and text inputs still allow selection even though long-press callouts are off elsewhere. → Task 3 Step 7 and Task 5 Step 4.
5. **A family device is asleep, off Wi-Fi, or never registered.** Expected: it is reported and skipped by name, every other device is still installed, and the run only fails if nothing was installed or an install errored. → Task 4 `summarize` and `parseDevices` tests.
