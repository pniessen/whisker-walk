# Corner Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A coin-sized, always-on corner map on the walk screen showing the area, the cat, zoomies rings, the active quest target and scenic spots, in a per-player "north up" or "turns with me" mode.

**Architecture:** A 2D `<canvas>` inside `#hud`, never part of the Three.js scene. Pure helpers (`src/ui/minimapmath.js`) do the geometry and decide which markers show. A per-walk map layer (shapes in world metres) is built once from area data and the scene. A small UI module (`src/ui/minimap.js`) paints it each frame from a frame snapshot that main.js assembles.

**Tech Stack:** Vanilla JS, Canvas 2D, Three.js 0.185 (scene reading only), Vite 8, Vitest 4. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-31-minimap-design.md`

## Global Constraints

- No new Three.js draw calls: the map is page UI, never added to `scene`.
- Never shown: golden mice, secrets, gifts, collectibles, carryables, critters, strays.
- Never covers the cat or the touch controls, in either handedness, on phone or desktop.
- Nothing blinks or pulses except the next ring during a race.
- Purely local: no wire events, never `walkRng`.
- No map in the den (`areaId === 'den'`).
- SAVE_VERSION stays 4; the new save field is additive and sanitised on load.
- Default mode `'north'`. A kid's explicit `'turn'` choice holds under reduced motion.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Tests: `npx vitest run --exclude '.claude/**'` (134 files / 3,283 tests passing at the start). Build: `npm run build`.

## Review Focus

1. **A walk with no real race** (`session.race` is the stub with `currentRing: 0`, or `state === 'done'`): no ring markers at all. Test in Task 2.
2. **Quest offered but not accepted** (`state === 'offered'`) and **completed** (`'complete'`): no quest marker. Test in Task 2.
3. **Targets far outside the radius, or straight behind the cat in turn mode**: pinned to the rim at the correct bearing, never drawn off the disc or at the centre. Test in Task 1.
4. **Left-handed co-walk on a phone**: map, area caption, roster and pause button don't overlap. Checked in the browser in Task 6.
5. **A tap on the map**: flips the mode, doesn't start a camera drag or move the cat, and survives a reload. Tests in Tasks 3 and 4, plus a browser check in Task 6.

### Task 1: Map geometry helpers

**Files:**
- Create: `src/ui/minimapmath.js`
- Test: `test/minimapmath.test.js`

**Interfaces:**
- Produces:
  - `MAP_RADIUS_M = 35`: default world radius shown.
  - `mapRadiusFor(areaId) -> number`: per-area radius in metres, default `MAP_RADIUS_M`.
  - `toMap(x, z, view) -> { u, v, inside }`
    - `view = { cx, cz, heading, mode, radiusM, radiusPx }`.
    - `heading` is the camera's forward yaw in radians, from `player.forward()` as `Math.atan2(-f.x, -f.z)`.
    - `mode` is `'north' | 'turn'`.
    - `u`/`v` are pixels from the disc centre; `v` is positive downward.
    - North mode: world −z is up.
    - Turn mode: the camera's forward is up.
  - `pinToRim({ u, v }, radiusPx, inset) -> { u, v }`: scales a point outside `radiusPx - inset` back onto that circle, keeping its bearing.

- [ ] **Step 1: Write the failing tests** in `test/minimapmath.test.js`:
  - `north mode: a point 10 m north of the cat is straight up`. With `view = { cx: 0, cz: 0, heading: 0, mode: 'north', radiusM: 35, radiusPx: 55 }`, `toMap(0, -10, view)` gives `u ≈ 0` and `v ≈ -10 * 55 / 35`, with `inside === true`.
  - `north mode ignores heading`. `toMap(10, 0, { ...view, heading: 1.2 })` equals `toMap(10, 0, view)`.
  - `turn mode: whatever is ahead is up`. With heading `Math.PI / 2` (forward is world −x), `toMap(-10, 0, turnView)` gives `u ≈ 0` and `v < 0`.
  - `turn mode: behind is down`. A point straight behind the camera has `v > 0` and `u ≈ 0`.
  - `outside the radius is flagged`. `toMap(0, -60, view).inside === false`.
  - `pinToRim keeps the bearing and lands on the rim`. Pinning `{ u: 300, v: -400 }` to `radiusPx: 55, inset: 6` gives a point at distance 49 with the same `atan2`.
  - `pinToRim leaves inside points alone`.
  - `mapRadiusFor('nowhere') === 35`.
- [ ] **Step 2: Run them and confirm they fail.** Run `npx vitest run test/minimapmath.test.js`. Expected: fails with an import error.
- [ ] **Step 3: Implement the four exports** in `src/ui/minimapmath.js`. It is pure: no DOM and no THREE.
- [ ] **Step 4: Run them and confirm they pass.**

### Task 2: Which markers show

**Files:**
- Modify: `src/ui/minimapmath.js`
- Test: `test/minimapmath.test.js`

**Interfaces:**
- Consumes: nothing beyond Task 1.
- Produces:
  - `mapMarkers(frame) -> Array<{ kind, x, z, ... }>`.
  - `frame` has this shape:
    ```
    {
      race: { state, currentRing, rings: [{x,z}], pad: {x,z} | null } | null,
      quest: { state, target: {x,z} } | null,
      scenics: [{ id, x, z }],
      visitedScenics: Set<string>,
      remotes: [{ x, z, color }],
    }
    ```
  - `kind` is one of `'ring'` (with `n` and `dim`), `'pad'`, `'quest'`, `'scenic'` (with `filled`) or `'remote'` (with `color`).
  - The cat is not a marker; the painter always draws it at the centre.
  - `mapMarkers` reads only these keys, so hidden things can't leak in through it.

- [ ] **Step 1: Write the failing tests**:
  - `running race shows the next ring bright and the one after dim`. With `currentRing: 2` and five rings, the result has exactly two ring markers: `{ n: 2, dim: false }` at `rings[1]` and `{ n: 3, dim: true }` at `rings[2]`.
  - `last ring has no dim follower`. With `currentRing: 5`, there is exactly one ring marker.
  - `idle race shows only the pad`. With `state: 'idle'` and a pad, there is one `pad` marker and no ring markers.
  - `done race and the stub race show nothing`. Both `state: 'done'` and `{ state: 'idle', currentRing: 0, rings: [], pad: null }` give no `ring` and no `pad` markers.
  - `quest shows only while active`. `'active'` gives one `quest` marker; `'offered'`, `'complete'` and `null` give none.
  - `scenic stars fill once visited`. Two scenics with `visitedScenics = new Set(['pier-end'])` give `filled: true` for pier-end and `false` for the other.
  - `remote cats keep their colour`.
  - `extra keys never become markers`. A frame carrying `goldMice`, `collectibles` and `secrets` arrays yields no markers for them.
- [ ] **Step 2: Run them and confirm they fail.**

### Task 4: The map layer and the painter

**Files:**

- Test: `test/minimap.test.js`, plus an update to `test/hud.test.js` if it pins the markup.

**Interfaces:**
- Consumes:
  - `toMap`, `pinToRim`, `mapMarkers` and `mapRadiusFor` from Tasks 1 and 2.
  - `flatFootprints(scene)` from `src/render/grass.js`.
- Produces:
  - `buildMapLayer(areaData, scene) -> { ground, edge, water: [], paths: [], blocks: [] }`.
    - World-metre shapes only (pure data).
    - `ground` is a CSS colour from `areaData.groundBounce`.
    - `edge` is `areaData.bounds`.
    - `water` comes from `areaData.waters`.
    - `paths` are the strips `flatFootprints` returns.
    - `blocks` are `areaData.colliders` circles with `r >= 1.0`, standing in for buildings and large props.
    - Call it before `mergeStaticProps` if it reads meshes. It reads only area data plus flat strips, which survive the merge, so the walk.js placement in Task 5 is safe either way.
  - `createMinimap(hostEl, { areaId, layer, mode, onToggle }) -> { update(view, frame), setMode(mode), get mode, show(), hide(), dispose() }`.
    - `view` is `{ cx, cz, heading }`; the module fills in `mode`, `radiusM` and `radiusPx`.
    - It redraws only when `view` moved more than 0.05 m or 0.01 rad, `frame`'s markers changed, or the mode changed, and at most 30 times a second.
    - The canvas is sized for `devicePixelRatio`.
    - A tap (`pointerup` within 10 px and 300 ms of `pointerdown`) calls `onToggle()`.
    - The element sets `pointer-events: auto` and calls `stopPropagation` on pointer events, so the orbit/joystick handlers never see them.
    - Markers outside the disc are drawn with `pinToRim(..., radiusPx, 6)`; the cat is always at the centre.
    - It has `aria-label="Map"` and `role="img"`.
- Look:
  - About 110 px across on phones (`body.touch-mode`) and 150 px on desktop.
  - Cream disc `#f4efe4` with a thin dark rim.
  - The cat is the strongest mark: a `#d8572a` dot with a nose pointing along the heading in north mode, and always up in turn mode.
  - Rings are gold `#e8a21f` with their number; dim rings are drawn at 45% alpha.
  - The quest marker is a teal drop; scenic stars are hollow or filled.
  - The rim badge shows "N" in north mode; in turn mode it shows a small arrow pointing to north.
